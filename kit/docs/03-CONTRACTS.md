## §3 Coming-soon page and preview bypass (`proxy.ts` / `middleware.ts`)

**Applies** to every request when `HOLA_COMING_SOON=1`, **except**:

- `/admin` and everything under it, `/api/…`, `/_next/…`
- `/favicon.ico`, `/icon.svg`, `/apple-icon.png`, `/manifest.webmanifest`, `/robots.txt`, `/sitemap.xml`
- static files under `/brand/`, `/fonts/`, `/media/` and any other `public/` file
- requests with a valid admin session or a valid preview cookie (below)

**Admin session:** the `payload-token` cookie is valid only when its JWT verifies and is not expired. Payload signs HS256 with the first 32 hex characters of SHA-256(`PAYLOAD_SECRET`), not the raw secret: `jwtVerify(token, new TextEncoder().encode(createHash('sha256').update(process.env.PAYLOAD_SECRET).digest('hex').slice(0, 32)))` with `jose` (the interceptor runs on the Node runtime). A cookie that is present but invalid (e.g. `payload-token=garbage`) is treated as a visitor.

**Preview bypass:**

- `GET <any page>?hola_preview=<HOLA_PREVIEW_KEY>` responds `307` to the same URL without the parameter and sets cookie `hola_preview` = hex `HMAC-SHA256(key=PAYLOAD_SECRET, msg="preview|" + HOLA_PREVIEW_KEY)`; `Path=/`, `HttpOnly`, `SameSite=Lax`, `Max-Age=2592000`, `Secure` only on HTTPS.
- A wrong key sets no cookie and gets the coming-soon page.
- A request whose `hola_preview` cookie equals that HMAC is served normally.

**The coming-soon response:**

- Status `503`; headers `Retry-After: 86400`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store`.
- A self-contained HTML page: `<html lang="es">`, `<title>Hola Egipto · Muy pronto</title>`, `<meta name="robots" content="noindex,nofollow">`, the stacked colour logo, the line `Muy pronto · Coming soon`, one sentence in each language, `papyrus` background, brand fonts.
- A WhatsApp button only when `whatsapp_number` is set.

## §4 Content model (Payload)

**Localization:** `locales: ['es', 'en']`, `defaultLocale: 'es'`, `fallback: false`.

**Rule for every field in the spec:** facts are shared and words are localized. A field the spec's "Synced" list names (prices, durations, group sizes, dates, availability, gallery, relationships, `featured`, `booking_mode`, coordinates) is **not localized**. Every text field is **localized**. This replaces the spec's translation-sync plugin: one document holds both languages.

## §6 Language rules

- `<html lang>` is `es` or `en`.
- The language switcher links to the same item in the other language, and is hidden on a page whose item is not `available` in the other language.
- Prices: EUR on Spanish pages, USD on English pages, from `price_from_eur` / `price_from_usd`. Spanish format `1.290 €`, English `$1,390` (`Intl.NumberFormat('es-ES', {style:'currency', currency:'EUR', maximumFractionDigits:0, useGrouping:'always'})`; `es-ES` does not group 4-digit numbers by default).
- The `<h1>` of a single item is exactly its `title` in the page language.

## §7 Inquiry API

**Token** (reusable within its validity window, not single-use): `GET /api/hola/token` → `200 {"token":"<ts>.<hmac>"}` with `Cache-Control: no-store`. `ts` is Unix seconds; `hmac` is hex `HMAC-SHA256(key=PAYLOAD_SECRET, msg="inq|" + ts)`. Valid when its age is between 3 s and 48 h.

**Endpoint:** `POST /api/hola/inquiry`, body JSON (`Content-Type: application/json`) or form-encoded (`application/x-www-form-urlencoded`, the no-JavaScript path).

| Field | Rule |
| --- | --- |
| `form` | `plan_my_trip` (default) \| `contact` |
| `lang` | required, `es` \| `en` |
| `token` | required, valid |
| `website` | honeypot, must be empty |
| `name` | required, 2–80 characters |
| `email` | required, valid email |
| `consent` | required, `1` |
| `adults` | required for `plan_my_trip`, integer 1–30 |
| `trip_id` + `trip_type` | optional; must point to an `available` tour/cruise/excursion (`trip_type` = `tour` \| `cruise` \| `excursion`) |
| `interests[]`, `length`, `date_mode` (`exact` \| `month` \| `flexible`), `date_from`, `date_to`, `month`, `children`, `children_ages`, `budget`, `hotel`, `group_type`, `whatsapp`, `channel` (`whatsapp` \| `email`), `message` (≤ 2000), `marketing`, `page_url`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid`, `fbclid`, `landing` | optional |
| `cf-turnstile-response` | required only when both Turnstile keys are set; verified server-side |

**Turnstile keys empty:** accepted when `HOLA_DEV_MODE=1`; otherwise answered `400 {"ok":false,"errors":{"form":"…"}}`.

**JSON responses:**

| Status | Body | When |
| --- | --- | --- |
| 201 | `{"ok":true,"id":<id>,"redirect":"<thank-you path in lang>?ref=<ref>"}` | valid |
| 422 | `{"ok":false,"errors":{"<field>":"<message in lang>"}}` | validation failed |
| 400 | `{"ok":false,"errors":{"form":"…"}}` | honeypot, bad/expired token, Turnstile |
| 429 | `{"ok":false,"errors":{"form":"…"}}` | more than 5 per `ip_hash` per hour |

**Form-encoded responses:** valid → `303` to the thank-you URL with `?ref=`; invalid → `303` back to `page_url` (or the form page) with `?errors=<comma-separated field names>#form`.

**Rate limit bypass and test flag:** when `HOLA_DEV_MODE=1` and the request has header `X-Hola-Test: 1`, the rate limit is skipped and the stored inquiry gets `holaSample: true`.

**Storage** (`inquiries`, created with the Local API): title `{name} · {trip title | "Sin viaje"} · {YYYY-MM-DD HH:mm}`; fields `form`, `trip` (polymorphic relationship), `interests`, `length`, `date_mode`, `date_from`, `date_to`, `month`, `adults`, `children`, `children_ages`, `budget`, `hotel`, `group_type`, `name`, `email`, `whatsapp`, `channel`, `message`, `consent_at`, `marketing`, `lang`, `page_url`, `utm` (group: `source`, `medium`, `campaign`, `term`, `content`), `gclid`, `fbclid`, `landing`, `status` (`new` default \| `replied` \| `won` \| `lost`), `tracked` (checkbox), `ip_hash` (hex SHA-256 of IP + `PAYLOAD_SECRET`), `holaSample`.

**Ref:** `<id>.<hex HMAC-SHA256(key=PAYLOAD_SECRET, msg="ref|" + id)>`.

**Thank-you tracking:** the thank-you page renders the `generate_lead` push only when `ref` is valid and the inquiry's `tracked` is false, then sets `tracked` to true. The page is never cached.

**Mail** — every message goes through one function, `sendMail()` in `src/lib/mail.ts`:

- **Team:** to `contact_email` (fallback `ADMIN_EMAIL`), `Reply-To` the traveller, all fields listed.
- **Traveller:** an auto-reply in their language with `reply_hours`.
- **While `HOLA_DEV_MODE=1`:** the recipient is replaced by `ADMIN_EMAIL`, the subject is prefixed `[DEV → <original recipients>]`, Cc/Bcc are dropped. If `ADMIN_EMAIL` or `SMTP_HOST` is empty, nothing is sent.
- **Every call** appends one line to `HOLA_MAIL_LOG`: `<ISO time>\tto=<final recipient or (not-sent)>\torig=<original recipients>\tsubject=<subject>`.

**Webhook:** if `N8N_WEBHOOK_URL` is set, POST the inquiry as JSON (id, created_at, lang, form, trip {id, type, title, url}, all fields, utm) after the response is sent (`after()`), timeout 5 s, header `X-Hola-Signature: sha256=<hex HMAC-SHA256(key=HOLA_WEBHOOK_SECRET, msg=body)>`.

**Retention:** `pnpm hola:retention` deletes inquiries older than 24 months whose `status` is not `won` (to be scheduled at deployment).

## §8 WhatsApp

`whatsappUrl(ctx)` in `src/lib/whatsapp.ts` returns `https://wa.me/<whatsapp_number>?text=<encodeURIComponent(message)>`.

- **Message:** `whatsapp_message_default` in the page language. On trip pages: ES `Hola, me interesa «{title}» — {url}`, EN `Hi, I'm interested in “{title}” — {url}` (`{url}` absolute).
- **Always** include `?text=` (the generic message when there is no trip), on every placement including the header.
- **Number empty:** no WhatsApp link or button is rendered anywhere (the layout keeps its shape).
- **Every rendered link** carries `data-he-event="whatsapp_click"`, `data-he-location="<header|sticky|sidebar|page|footer|coming_soon>"`, and `data-he-trip="<id>"` when there is a trip.

## §9 CLI scripts (`pnpm -s hola:<name>`)

Each script is `payload run scripts/hola/<name>.ts --` (the trailing ` --` is required: without it `payload run` drops flags such as `--dry-run` and turns numeric arguments into numbers) or `tsx scripts/hola/<name>.ts` with `.env.local` loaded. Scripts use top-level `await` and treat every argument as a string. All run against the database in `.env.local` through Payload's Local API, exit `0` on success, print only what is listed (logs to stderr), never prompt, and never print secrets. Scripts that change content call `POST /api/hola/revalidate` (§16) at the end when the server answers on `NEXT_PUBLIC_SITE_URL`.

| Command | Output / effect |
| --- | --- |
| `hola:health` | `{"db":true,"payload":true,"collections":<n>}` |
| `hola:schema` | JSON: `{"collections":{"<slug>":["<field>", …]}, "globals":{"<slug>":["<field>", …]}, "locales":["es","en"], "defaultLocale":"es"}` — top-level field names, with group/array children as `parent.child` |
| `hola:seed` | idempotent: launch terms, pages (§5), `site-settings` defaults, `navigation`, placeholders, then `hola:samples create` |
| `hola:placeholders [--force]` | generates the branded placeholder images into `media` (`holaSample: true`) |
| `hola:samples create` | idempotent; the sample set from content rules §2 |
| `hola:samples delete [--dry-run]` | deletes every document with `holaSample: true` in every collection, including their media files; `--dry-run` prints `{"would_delete":{"<collection>":n,…}}` and changes nothing |
| `hola:samples count` | `{"tours":{"es":n,"en":n},"cruises":…,"excursions":…,"destinations":…,"guides":…,"media":n,"inquiries":n}` — per-locale counts are sample docs `available` in that locale |
| `hola:urls` | TSV, one row per URL to test: `group<TAB>lang<TAB>path<TAB>expect<TAB>index`. `group` ∈ `home`, `archive`, `single`, `term`, `page`, `search`, `404`; `path` starts with `/` and ends with `/` (plus query for search); `expect` is the HTTP status; `index` is `1` or `0`. ## §11 Security behaviours

- `poweredByHeader: false` (no `X-Powered-By`).
- Every front-end response has `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `X-Frame-Options: SAMEORIGIN`, and `Content-Security-Policy-Report-Only`.
- REST access: logged-out `GET /api/users` and `GET /api/inquiries` answer `401` or `403`. Public read of the content collections is allowed.
- No user called `admin`; the run creates no permanent users.
- No kit file is reachable over HTTP: nothing from `kit/` is copied into `public/` except the brand files listed in `kit/brand/README.md`.

## §16 Caching and revalidation

- Content pages use ISR. Payload `afterChange`/`afterDelete` hooks revalidate the affected paths; a `site-settings` or `navigation` change revalidates the whole site.
- Hooks must not throw when run outside the Next.js server (CLI scripts).
- `inquiries` has no revalidation hooks (the thank-you page updates `tracked` while rendering, where `revalidatePath` throws).
- `POST /api/hola/revalidate` with header `x-hola-revalidate: <HOLA_PREVIEW_KEY>` and body `{"all":true}` revalidates the whole site and answers `200 {"ok":true}`; a wrong or missing header answers `401`.
- The thank-you page, search and anything reading `searchParams` is dynamic.
